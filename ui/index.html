How backup works

The phone sends a manifest (what it has, with a SHA-256 per file), the desktop answers with what it lacks, the phone uploads those, resumable. Files live under /library, content-addressed, so a track from two phones is stored once. A track that leaves the phone is kept here and shown as "not on phone".

Embedded relay off

Phones add under Stations → relays. Their social traffic then goes through this desktop; nothing else sees who follows whom.

Upstream relays

Events from paired phones and this desktop are mirrored out; followed stations are pulled in. Any wss:// works, including your own.

Self-hosted funnel

Run cued-funnel edge on any box with a public address and start cuedd --funnel host:8771 --funnel-psk …. The desktop connects outbound; the edge forwards TLS bytes it cannot read; the phone pins the certificate from the QR code. See docs/funnel.md.

Companion downloads

The phone's Downloads → Backend → Companion (LAN) takes this desktop's address as is. Jobs run in the Python worker with spotdl and land in the library. A paired phone sends its token; anything else on the Wi-Fi is refused unless you allow it here.

Theme colours

Account

An account is one key pair shared by every device you bind to it. Others only ever see the public key (the npub) and the name; the private key stays on your devices and in sealed transfers between them.

Devices on this account

Unbinding appends a block to the chain; the device keeps its copy of the key until it is wiped there.

Private key

Whoever holds the private key is this account. Keep it to yourself; only the public key is ever shown to friends, stations and relays.

Start over

Makes a fresh key pair; the old one is backed up on disk. Friends and phones bound to the old key will not follow.
