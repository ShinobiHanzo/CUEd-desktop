How backup works

The phone sends a manifest (what it has, with a SHA-256 per file), the desktop answers with what it lacks, the phone uploads those, resumable. Files live under /library, content-addressed, so a track from two phones is stored once. A track that leaves the phone is kept here and shown as "not on phone".

Following

This desktop's station

Broadcast what the desktop player plays: metadata only, signed with this desktop's key, through the embedded relay and the upstream relays.

Identity

The key pair is identity.json in the data directory.

Embedded relay

Phones add under Stations → relays. Their social traffic then goes through this desktop; nothing else sees who follows whom.

Upstream relays

Events from paired phones and this desktop are mirrored out; followed stations are pulled in. Any wss:// works, including your own.

Self-hosted funnel

Run cued-funnel edge on any box with a public address and start cuedd --funnel host:8771 --funnel-psk …. The desktop connects outbound; the edge forwards TLS bytes it cannot read; the phone pins the certificate from the QR code. See docs/funnel.md.

Companion downloads

The phone's Downloads → Backend → Companion (LAN) takes this desktop's address as is. Jobs run in the Python worker with spotdl and land in the library.
